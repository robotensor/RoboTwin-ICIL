# RoboTwin-ICIL v0.1.0

Robotensor's first release of RoboTwin-ICIL, a one-demonstration in-context imitation
learning benchmark built on RoboTwin 2.0.

Every episode generates one successful expert demonstration at evaluation time, rebuilds
the exact initial scene, verifies its fingerprint, and asks a frozen policy to reproduce
the demonstrated behaviour. The score is **Same Scene 1-Demo Success Rate**, reported
overall, by skill category and by task. Rejected expert attempts are recorded separately
and never enter the policy's score denominator.

## Included

- A catalogue of all 50 RoboTwin tasks across seven manipulation skill categories,
  with arm requirements checked against the pinned upstream experts.
- Standalone evaluation, expert surveys, resumable run records, reports, and optional
  demonstration and rollout videos. `eval` and `survey` select all tasks by default;
  `--task NAME` selects one, and `--arms 1` keeps the 26 strictly one-arm tasks.
- Aloha-AgileX and dual Franka-Panda embodiments, with robot-specific action widths.
- Model-independent demonstrations and a policy adapter interface, plus dummy and
  replay policies.
- Saved demonstration prompts through `materialize` and evaluation through `run-unit`,
  with scene verification and separate policy and harness failure accounting.
- An optional competition plugin with deterministic unit derivation, prompt checks,
  and benchmark source verification; both distributions are versioned **0.1.0**.
- Simulator installation paths for the reference GPU stack and Blackwell GPUs.

## Validation and scope

The documented replay oracle scored **18/18 on nine tasks**, two episodes per task,
on Aloha-AgileX, with no scene fingerprint mismatches. This is a historical harness
validation result: replay uses the expert's recorded joint trajectory. It is neither
a learned-policy result nor a measurement across the full 50-task catalogue.

This release implements Same Scene only. It does not measure scene generalization,
and no learned ICIL policy result is included. The optional `franka_1arm` competition
selection has four tasks chosen from a small survey; its stacking stand-in can switch
arms on other scenes. See the [raw survey results](../results/survey-franka-seed0.json) and
[competition guide](../../competition/README.md#the-franka_1arm-suite) for selection criteria and limitations.

## Get started

```bash
git clone --branch v0.1.0 --recurse-submodules https://github.com/robotensor/RoboTwin-ICIL.git
cd RoboTwin-ICIL
bash scripts/install_robotwin.sh
```

Then, in the installed simulator environment:

```bash
robotwin-icil eval --policy replay --task click_bell --episodes 1 --seed 42 --run-dir runs/smoke
robotwin-icil report runs/smoke
```

See [installation](../install.md) and [policy adapters](../policies.md). Release wheels
contain the Python packages; running simulation also requires the pinned RoboTwin
submodule, its assets, and the simulator environment. Use the recursive clone above
for a simulator checkout. The Python packages are distributed as release assets;
this release does not publish them to PyPI.

Served policies and the competition plugin also require `icil-policy`, currently
distributed through Robotensor's private orchestrator repository. Local policy
adapters and the replay oracle work without that dependency.
